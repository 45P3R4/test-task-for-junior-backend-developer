# Recurrance

Функционал для создания повторяющихся задач

## Возможные сценарии

- Помимо обычных сценариев, вроде ежедневных задач или определенный день недели, могут существовать более комплексные условия, например будние дни четных дней месяца, в задании это реализовано при помощи модификаторов. Таким образом можно закрыть большинство потребностей повторяемости задач.

- Отдельным сценарием можно выделить последний день месяца (например для ежемесячной инвентаризации), возникает проблема: не во всех месяцах ровно 31 день, эта возможность реализована отдельно: `RecurrenceType = "monthend"`

## Как принимались решения

Решения принимались на основании уже написанного кода, новый функционал расшияет его, но не изменяет. Для структур выбирался наиболее компактный набор полей для экономии ресурсов БД и скорости обработки запросов, так и появилась идея модификаторов.

Модель БД по схеме один к одному, на каждой задаче может быть только одно правило повторяемости, внешний ключ (task_id) также соответствует первичному ключу.


Маршруты:

- `POST /api/v1/tasks/{id}/recurrence`
- `GET /api/v1/tasks/{id}/recurrence`
- `PUT /api/v1/tasks/{id}/recurrence`
- `DELETE /api/v1/tasks/{id}/recurrence`

Пример JSON:
`{
  "recurrence_type": "monthly",
  "recurrence_modifiers":["weekdays"],
  "days": [5, 20]
}`
